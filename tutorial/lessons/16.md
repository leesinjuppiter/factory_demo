# 16 分层验证整个项目

目标：分清例子测试、数据库测试、模型测试与真实流程。

## 动手顺序
1. 先运行无数据库、无模型的小例子检查。
2. 再运行真实 Runner + 内存存储实验。
3. 补齐练习测试文件，确认第 7/12/14 节的数据库、权重和前端都已准备。
4. 在练习目录运行 API 与推理测试。API 用教学库内唯一 schema，结束只清理自己的 schema；真实推理测试加载可信权重。

```powershell
& $py -B tools\check_examples.py
& $py -B examples\runner_lab.py
& $py -B tools\course.py apply 16
Push-Location practice\factory_demo
& $py -B -m pytest tests\test_api.py tests\test_inference.py -q --basetemp runtime\pytest-tmp
Pop-Location
```

这些命令属于你的学习验收步骤。本课程制作只运行前两类不连数据库、不加载模型的检查，不能把原项目通过的 20 项测试冒充为练习项目已重新通过。

## 继续做真实 50 张流程
让练习服务运行于 8876，在另一个终端执行：

```powershell
& $py -B practice\factory_demo\scripts\smoke.py --url http://127.0.0.1:8876 --output practice\factory_demo\runtime\evidence\smoke50.json
```

该命令会实际创建三个任务并推理 50 张，前提是权重和数据源路径就绪；完成课程之前不必提前执行。

分别记录静态检查、接口替身、真实数据库、真实模型、真实 HTTP、浏览器的证据。截图不能证明事务一致性；构建成功也不能证明模型可加载。练习：为“提交失败不能显示成功帧”写一个故障注入用例构想。

## 完整4911张性能测量：从记录到优化判断

本轮服务器实际输入4911张1580×1080图片，RTX3080Ti / PyTorch CUDA FP32 / batch1；基线34.195张/秒，带数据库、快照、统计与展示发布的应用链路19.418张/秒。读图/哈希/解码17.717ms与前向13.513ms处于相近量级，不能只优化模型。

动手步骤：

1. 冻结输入清单、权重哈希、环境和阈值；每帧用run_id/frame_id关联，防止图片与计时错位。
2. 用perf_counter_ns记录不重叠阶段；GPU异步操作在计时边界同步。完整保留失败输入，不能删除慢帧。
3. 每帧记录read/hash/decode、pre/forward/post、快照、统计、DB、publish；另记录并行预览与WS。不要把并行时间加进主链路。
4. 以实际墙钟计算FPS，逐帧报告均值/P50/P95/P99；界面total的倒数不能替代应用吞吐。
5. 验证所有必需事件各4911条、哈希全部对应、服务恢复正常、追踪有footer，再写结论。
6. 根据实测提出单因素实验。预览重复解码12.032ms、缩放23.768ms值得验证；本轮未实施优化。

约束：正式项目的benchmark_full4911.py会控制服务器8765实例，**不能复制到教学练习区直接运行**。课程仅同步profiling模块与参考测试；你可先在独立小示例中学习计时。生产42fps预算23.810ms，本轮活动周期均值51.040ms；输入分辨率不同，尚不证明工业能力。第一次追踪尾部丢失后保留失败证据并补跑，不能用不完整分位数冒充完整结果。
