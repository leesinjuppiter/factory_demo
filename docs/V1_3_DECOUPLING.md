## 2. 运行和展示的两条路径

生产者按后台任务运行，不由浏览器连接触发。合法图片读取、原图固化、推理、数据库提交继续由 Runner 推进。成功提交的帧交给展示模块；独立预览工作线程编码 JPEG，不在推理工作线程中等待浏览器发送。

展示模块发布完整的协议快照：首次无画面时可收到“结果已有、预览尚未就绪”；已有完整画面时保留它，直到后续预览编码完成再发布对应的完整帧。编码中的帧允许完成，仅替换待编码槽，避免高频输入导致永久没有画面。浏览器完成图片获取和解码后才提交画面与检测框，不能把新框画在旧图上。后台历史通过历史适配器进入同一画布，仍使用已保存原图与结果。

约束：预览分支可以跳过旧展示任务，但检测输入和数据库记录不因此丢弃。预览队列和每个浏览器队列均有界；慢浏览器不影响其他浏览器。终端停止、模型错误、数据库提交失败不等于正常的“未检出”。

## 3. 已确认的生产边界

用户确认：单相机、4096×2168、目标至少 42fps；候选 acA4096-40um/uc；带速 0.45m/s；生产先落本机硬盘再读取；本版仅本机访问。+8m 是现场平面信息，9m 是带长，不能代替相机高度或拍摄到动作距离。

模拟器与持续目录接口用于验证来源和身份协议。模拟发布达到某个频率，不代表推理和端到端也达到该频率。没有真实捕获时间就报告 null，另给文件发布/摄入时间；不能把模拟回放时间当曝光时刻。

## 4. 数据库失败仍是明确限制

实时状态维护内存快照，不再每次 /api/status 查询最新帧数据库。控制意图与实际帧边界分开：接口受理暂停后，当前原生模型调用仍需结束。实际帧和汇总必须成功保存才发布为成功结果；存储失败进入任务失败路径。

约束：这不是无数据库模式，服务冷启动仍需 PostgreSQL；历史和导出继续查库。内存状态可见不代表新结果可无限离线产生。当前不引入归档丢弃、离线 spool 或“失败照常执行”的生产策略。

## 6. WS 运行依赖与独立验证

API 依赖新增 `websockets==15.0.1`，仅安装基础 uvicorn 不保证 WebSocket 可用。使用指定 yolo_v5_obb 环境按 `requirements-api.txt` 检查依赖；不能用 HTTP 200 代替真实 WS 握手测试。

独立模拟后端：在项目目录执行 `python -B scripts/mock_display.py --port 8879`，访问 `http://127.0.0.1:8879/`；须先完成 `frontend` 构建。它直接托管相同 dist，以固定模拟数据验证协议，不连接数据库或加载模型。

持续任务的 P50/P95 统计最近最多 1000 个成功样本，均值为累计成功样本；有限任务保留该轮完整样本。它们是当前处理耗时，不能代替采集到执行动作的端到端延迟。
