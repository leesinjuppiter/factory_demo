# 小数据集验证与后续性能测试

## 1. 本版测试解决什么问题

本版先证明图片能够完成“读取 → 真实推理 → OBB 结果 → 持久化 → 浏览器显示 → 导出”。50 张小数据集的计时可以帮助发现明显瓶颈，但不用于证明最终吞吐、模型精度或工业连续运行能力。

指定数据集位于：

```text
C:\Users\13480\Desktop\codex_\yolov5_obb-master\dataset\dataset4911_obb_smoke_50
```

其 train/val/test 分别为 30/10/10 张，总计 50 张；这些图片是用于代码检查的有意覆盖样例，包含背景、边界与稀有类别。`bottle` 仅在训练子集中出现，因此不能据此评价其验证/测试能力。

默认权重实测为 8 类，顺序是 `coal, rockbolt, mesh, bottle, stick, board, cap, plate`；数据集是 7 类，`bottle` 的数据集 ID 是 6，而权重 ID 是 3，`stick/board/cap` 也依次错位；`plate` 没有对应真值类别。**不能直接按整数 ID 计算精度。** 完整数据集精度评估前，先按类别名建立映射并决定额外类的处理，不得静默丢弃。

## 2. 测试顺序

1. 检查解释器、依赖、数据库、权重哈希与模型类别。
2. 单张图片推理，检查非空框、坐标有限性和画面叠加。
3. 运行 `smoke_test`，核对 10 张图片的成功/失败和输出。
4. 分别运行 `smoke_val` 与 `smoke_train`，保持原划分，仅作流程检查。
5. 验证暂停/继续/停止、重复创建、坏图、无检测、历史、导出和重启恢复。
6. 浏览器检查实际画面、空态、错误态和两种桌面分辨率。

如果默认阈值使部分图片无框，这本身不是流程失败。为了覆盖框显示，可以另运行显式标记的低阈值测试；不能将测试阈值包装成推荐业务阈值。

## 3. 必须记录的运行条件

| 条件 | 记录内容 |
|---|---|
| 代码 | 项目版本或交付时间，推理 vendor 来源 |
| 模型 | 权重 SHA-256、名称、实际类别顺序 |
| 环境 | Python 路径、Python/Torch/OpenCV 版本、设备、CPU 线程 |
| 输入 | 数据源、文件数、分辨率、文件类型；是否重复或已缓存 |
| 推理 | 输入尺寸、置信度、NMS IoU、max_det、batch、精度 |
| 调度 | 目标回放 FPS、是否暂停、浏览器是否打开 |
| 持久化 | 数据库类型、所在设备、是否启用结果与图片保存 |
| 计时 | 预热规则、统计样本数、排除项、分位数算法 |

必须比较相同条件。不同输入尺寸、阈值、精度、后处理或显示链路的结果，不能直接归因为推理引擎本身。

## 4. 各时间指标的解释

| 指标 | 含义 | 不能替代 |
|---|---|---|
| 读取/解码 ms | 从文件得到可推理图像的时间 | 磁盘带宽基准 |
| 预处理 ms | letterbox、布局与类型转换、归一化 | 模型 forward 时间 |
| 推理 ms | 模型实际执行的时间 | 整个请求或页面响应时间 |
| 后处理 ms | 候选解码、旋转 NMS、坐标还原和结果组装 | 仅 NMS 时间，除非另行拆分 |
| 处理总 ms | 实现定义的图片处理区间 | 浏览器端到端延迟 |
| mean/P50/P95 | 已记录成功图片的处理耗时分布 | 长期生产 SLA |
| 处理能力 FPS | 按耗时计算或实际执行区间统计的速率，必须注明公式 | 目标回放频率、显示更新率 |

模型加载、预热、数据库写入、调度等待、网络传输与浏览器绘制是否在某指标中，必须以实际代码和验收记录说明为准。不要自行把所有字段相加称为端到端延迟。

本版实际 total = read + preprocess + inference + postprocess，排除快照写盘、数据库、限速等待、传输和显示。摘要使用成功帧，P50/P95 由 NumPy percentile 默认线性插值计算；只有一个成功样本时两个分位数相同。加载时的单次 640×640 预热不计入逐图计时，但新尺寸/长宽比的第一帧可能仍有额外开销。

若 `fps = 1000 / mean_ms`，它是测得处理区间的理论串行处理能力，不能代替包含数据库与调度等待的实际墙钟吞吐。若用运行墙钟计算，应同时说明暂停、加载和限速是否包含在内。

本版界面实际采用前一种 `1000 / mean_ms` 公式。默认目标回放 1 FPS，即使处理能力大于 1 FPS，页面也不会因此每秒处理更多图片。

## 5. 完整数据集的建议协议

1. 将完整数据集图片目录加入本机配置，保留原训练、验证、测试归属。若超过单任务限制，按明确分片运行并在外部合并结果，不静默截断。
2. 使用冻结的最终权重、固定参数和相同软硬件环境。
3. 先运行独立预热图片，记录预热次数和是否已完成尺寸初始化。
4. 分别测无界面纯推理链路和带展示/数据库的应用链路，报告两个口径，不只选较快的一个。
5. 每个条件重复若干轮，保留逐图原始计时；报告样本数、均值、中位数、P95 和波动。
6. 记录失败图片与原因，不把失败样本无声排除；明确分母是输入数还是成功数。
7. 如需比较 PyTorch、OpenVINO、TensorRT，先完成相同图片的数值/检测结果对齐，再比较速度。
8. 长时间运行另测内存、磁盘增长、数据库占用和连接恢复；短样本耗时不能代替稳定性试验。

Windows 后台负载、CPU 电源模式、线程数、首次磁盘读取和 OS 缓存都会影响结果；重复测试应记录环境变化。不得为了提升某个方案的结果而只为它预热缓存。

## 6. 精度评估需单独进行

工作台显示的是模型输出，不执行真值匹配。完整数据集精度评估需要先确定：类别映射、困难样本规则、旋转 IoU 算法、AP 计算实现、测试划分和置信度扫描策略。

特别注意旧仓库的某些验证路径可能报告 HBB 指标。即使模型输出 OBB，也不能在未经核对时把其 `mAP` 写成旋转框 mAP。

显示置信度不等于准确率；空检测比例不等于漏检率；每图框数不是独立物体追踪计数。小数据集中训练图片的推理结果不得用来说明模型对未见数据的泛化。

## 7. 导出与证据归档

每次测试至少保留运行 JSON、逐图 CSV、环境信息和启动参数。页面截图用于证明可视效果，不能替代逐图原始结果。

JSON 优先用于完整结构化分析；CSV 用于表格检查。绘框 PNG 用于人工核对坐标与结果，不是新的人工标注。

页面下载会在浏览器内构造 Blob，超时为 60 秒，不适合很大的导出结果；大量图片/目标建议直接使用 HTTP 下载工具将 `/api/runs/<运行ID>/export?format=json` 流式写入本机文件。后端按100帧分页输出，不一次把整个运行加载进内存。若连接中断，部分文件不算成功导出，应重新下载并校验JSON解析及帧数。

JSON 根对象包含 `protocol_version`、`run` 和 `frames`。CSV 使用 UTF-8 BOM，每个目标一行；无检测/失败图片也保留一行。列为 `run_id,frame_id,name,frame_status,error,class_id,class_name,confidence,polygon_pixels,total_ms`。因此 CSV 行数可能大于图片数，不能直接以行数当处理图片数；应按 run_id + frame_id 去重。以公式字符开头的文本会加单引号以保护电子表格打开安全，原始结构化文本以 JSON 为准。

本版不提供自动清理。完整数据集测试前确认 PostgreSQL 与项目数据目录的可用空间；备份数据库时还应保留对应配置、权重哈希与必要的原图文件。
